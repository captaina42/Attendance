# Deploy AttendanceSecure

The app is **one Node service**. It serves the staff pages, the student app, the JSON API,
the PWA files and the SQLite database from the same origin. That is deliberate: the
session cookie, the camera, the passkey and the live polling all depend on being on one
HTTPS origin, so there is no separate frontend to host and no CORS to configure.

```
public/            staff pages + student app + manifest + service worker  (static)
server/            Express API, session lifecycle, WebAuthn verification
/data              attendance.db + private_uploads/photos  (persistent disk)
```

## 1. What you need

- A GitHub repository containing this folder.
- A host that runs Node 22 **and can attach a persistent disk**. SQLite and the captured
  photos live on that disk; a host with an ephemeral filesystem would lose attendance on
  every deploy. Render, Fly.io, Railway, a VPS or any Docker host all work.

Render is the shortest path because `render.yaml` in this repository already describes the
service, the health check, the environment variables and the 1 GB disk. Its free tier does
**not** include disks, so this needs the Starter plan (~$7/month). If you would rather not
pay, deploy the same `Dockerfile` on a machine you already have (see section 5).

## 2. Deploy on Render

1. Push this folder to GitHub.
2. Render Dashboard → **New → Blueprint** → choose the repository. Render reads
   `render.yaml` and shows the `attendsecure` service.
3. Fill in the prompted values:

   | Variable | Value |
   | --- | --- |
   | `APP_ORIGIN` | your service URL, e.g. `https://attendsecure.onrender.com` (you can paste it after the first deploy and redeploy) |
   | `ADMIN_EMAIL` | the lecturer's email |
   | `ADMIN_NAME` | the lecturer's name |
   | `ADMIN_PASSWORD` | a password of 8+ characters |

   `JWT_SECRET` is generated by Render. `DATA_DIR=/var/data`, `NODE_ENV=production` and
   `TRUST_PROXY=1` are already set.
4. **Create** and wait for the build. The start command runs `scripts/seed.js` first, which
   creates the lecturer account and default courses only if they do not exist yet.
5. Check `https://<your-service>/api/health` returns `{"ok":true,"app":"AttendanceSecure"}`.
6. Set `APP_ORIGIN` to the final HTTPS URL and redeploy. This value is what passkeys are
   bound to; if it is wrong, registration fails with a security error on the phone.

## 3. Environment variables

| Name | Required | Purpose |
| --- | --- | --- |
| `APP_ORIGIN` | yes in production | Public HTTPS origin. Must match the address users open. |
| `RP_ID` | no | WebAuthn Relying Party ID; defaults to the hostname of `APP_ORIGIN`. |
| `RP_NAME` | no | Name shown in the passkey prompt. Default `AttendanceSecure`. |
| `JWT_SECRET` | yes | Signs login cookies. Any long random string; Render generates one. |
| `DATA_DIR` | yes with a disk | Folder holding `data/` and `private_uploads/`. |
| `ADMIN_EMAIL`, `ADMIN_NAME`, `ADMIN_PASSWORD` | first run | Seed the first lecturer account. |
| `TRUST_PROXY` | behind a proxy | `1` so the HTTPS protocol and client IP are read correctly. |
| `PORT` | no | Defaults to 3000; Render sets it. |
| `COOKIE_SECURE` | no | Defaults to `true` when `APP_ORIGIN` is https. |

Never commit a real `.env`. Locally, copy `.env.example` to `.env`.

## 4. Install it on a phone

The app must be opened over **https://** on a phone: the camera (`getUserMedia`), the
fingerprint prompt (WebAuthn) and the service worker are all blocked on plain `http://`
non-localhost origins.

**Android (Chrome)**

1. Open the deployed URL.
2. Sign in — you land on the student or the staff dashboard automatically.
3. Menu (⋮) → **Install app** (or the install banner) → **Install**.
4. Launch it from the home screen: it opens standalone, with the splash screen and the
   `#11163f` theme colour, and works offline for the shell while showing a clear banner
   when the network is gone.

**Samsung Internet**: open the URL → menu → **Add page to** → **Home screen**.

**Desktop Chrome/Edge**: install icon in the address bar, or the **Install app** button in
the staff sidebar / student profile.

iPhone: Safari → Share → **Add to Home Screen** (installs as a standalone web app; iOS has
no `beforeinstallprompt`, so the app tells the user this instead of failing silently).

## 5. Deploy anywhere else (Docker)

```bash
docker build -t attendsecure .
docker run -d -p 8080:8080 -v attendsecure-data:/data \
  -e APP_ORIGIN=https://your.domain \
  -e JWT_SECRET="$(openssl rand -hex 48)" \
  -e ADMIN_EMAIL=you@example.com -e ADMIN_PASSWORD='ChooseAStrongOne' \
  attendsecure
```

Put a TLS-terminating proxy (Caddy, Nginx, or the platform's router) in front and set
`TRUST_PROXY=1`. The volume must be mounted at `/data`.

## 6. Verify a deployment

1. `GET /api/health` → `{"ok":true}`.
2. Browser shows the install prompt and `/manifest.webmanifest` loads with
   `display: standalone` and three icons.
3. Lecturer signs in at `/` → redirected to `/dashboard.html`; create a session.
4. Student signs in on the phone → redirected to `/student/`; the session appears only after
   **Activate attendance**.
5. Student taps **Verify identity** → the phone shows its own fingerprint/face sheet and
   creates a passkey (first time) or verifies it (later).
6. Camera opens, photo is captured, attendance is submitted as **verified**.
7. Lecturer's live page shows the student under **Submitted**, the countdown runs, and
   **Close session** makes the student page show *Attendance Session Closed*.

## 7. Operational notes

- **Back up** the whole `DATA_DIR` (database + photos). SQLite is a single file plus its
  `-wal`/`-shm` siblings; stop the service or use `sqlite3 .backup` for a consistent copy.
- **One instance only** unless the database moves to a server DB. SQLite on a shared disk
  with several instances will corrupt under write contention.
- Photos are written to `private_uploads/` and are never served statically; only the
  lecturer's report API exposes them (and only to the owning lecturer).
- Passkeys are bound to the hostname. Moving to a new domain means students enrol again.
